# PR 본문 템플릿 (한국어)

아래 구조를 그대로 사용한다. `<...>` 안내문은 실제 내용으로 바꾸고, 해당 내용이 없으면 `해당 없음`으로 쓴다.

```markdown
## 개요

<이 PR이 무엇을 하는지 1~2문장>

## 변경 배경

<왜 필요한 변경인지. 이슈나 요구사항이 있으면 링크 (예: Closes #12). 근거가 없으면 해당 없음>

## 변경 사항

- <사용자에게 보이는 변화 또는 핵심 코드 변경>
- <...>

## 검증

- [ ] 테스트 통과 (`<실행한 명령어>`)
- [ ] 린트 통과 (`<실행한 명령어>`)
- [ ] 빌드 통과 (`<실행한 명령어>`)
- [ ] 수동 확인 (<확인한 내용>)

<테스트를 새로 추가했다면 무엇을 검증하는지 한 줄>

## 리뷰어 참고

<주의해서 볼 부분, 호환성에 영향을 주는 변경, 설정·의존성 변경. 없으면 해당 없음>

## 스크린샷

<UI 변경이 있을 때만. 없으면 해당 없음>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## 작성 지침

- **변경 사항**은 파일 목록이 아니라 동작 단위로 쓴다. 파일 목록은 diff에서 볼 수 있다.
- **검증**은 실제로 실행해서 확인한 항목만 `[x]`로 바꾼다. 실행하지 않았거나 이 PR에 해당하지 않는 항목은 `[ ]`로 두거나 줄을 삭제한다.
- 마지막 attribution 줄은 항상 맨 끝에 둔다.
